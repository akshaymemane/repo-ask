# Compatible health projection

Retain `opendevin.health/m0.1`: existing components, top-level fields and model keys remain. The legacy-only builder retains its original response. When application services are composed:

- `components.index` uses IndexService storage when enabled. `persistent: true` identifies the persistent-index service, including its in-memory test configuration. `repository_count` is the sum of `counts.{ready,indexing,failed,not_indexed}`; these cover index sources plus catalog records not yet registered as sources. Disabled index sources count as not indexed. Otherwise latest queued/running/waiting/paused run counts as indexing; latest failed run counts as failed; otherwise an active snapshot counts as ready; otherwise not indexed. Ready means a saved snapshot exists, not a freshness or complete-coverage guarantee. Failed runs take precedence over a retained usable snapshot. `latest_failure_code` is the most recently updated failed index run's code, or null, with deterministic row ordering. Historical failures remain until removed. Any failed bucket degrades index and overall health.
- `components.model.roles.{ask,planning}` contains only `status`, `adapter`, and `destination` (destination kind, never endpoint/disclosure). Unassigned becomes `not_configured`; assigned role status preserves provider readiness (`untested`, `ready`, `blocked`, etc.). Existing top-level model status remains configured/not_configured for the Ask assignment, with adapter/destination mirroring Ask. `probed: false` remains accurate. Legacy --model is used only without application services.
- `components.execution` contains `status`, `runtime_status`, `docker_code`, `agent_code`, `active_session_count`. Status/runtime come from `services.execution_status()`; only codes are copied, never reason or recovery payload. Current production execution_status has no Docker/agent evidence, so those codes are `not_checked`. No probes or false readiness claims are introduced. Active sessions are counted from the session service's durable active-state set (includes queued/waiting/stopping); none are exposed individually. Without sessions count is zero. No-services legacy health has no execution key, preserving its shape.

Settings System health fetches this existing route when opened, renders plain words, and preserves the existing host's loading presentation until a valid response. It renders no raw provider or runtime records. The existing app.js consumer keeps accepting the m0 contract prefix; no out-of-scope app.js change is necessary.
