# Integration notes

Construct RoutingService, PlanService, then ConversationService using the same Store, JobQueue, IndexService and ProviderService. Register `ask.answer: conversations.run_answer` in Worker. Register `conversations.purge_repository` with the catalog's repository purge hook; it must run before physical source removal or regardless of ordering (it checks durable IDs). Coordinator owns HTTP/lifecycle registration. Do not expose PlanService source/profile_version_id/generation arguments to HTTP. No schema migration beyond accepted schema6 is added.

Collection shapes follow the contract. `PlanService.get/create/save_version` return plan metadata plus a `version` object; the version contains content/hash/provenance/scope_revision/readiness. Conversation.get contains the first 100 ordered messages and messages_next_cursor; use additive list_messages(id,limit,cursor) for earlier continuation. Plans have plans_next_cursor; list_plans handles continuation. History is bounded to 12 prior messages/8KB for generation and only the current scope revision; stored history is never silently overwritten. Message outputs additionally carry their original scope_revision/repository_ids. Answer-run public identity is `id` (run_id in job result); send includes job/message/conversation IDs.

Unscoped explicitly resolved routing adopts selected scope atomically and increments revision before generation. Generic matches do not auto-select a writable target. If no scope resolves, the provider can give an explicitly qualified unknown/no-evidence answer; plans cannot invent scoped citations. Errors are stable codes without provider exception strings. Source is passed as untrusted JSON data and rechecked before transmission/finalization. Invalid JSON/evidence receives at most one repair. Answer factual support still needs independent semantic review: identity validation cannot prove every natural-language claim follows its citation.

Domain output and plan creation commit together under a live lease/scope fence. A reclaimed job whose domain transaction already completed returns without generating again, allowing the queue to acknowledge safely. Retrying failed/cancelled runs keeps user identity and creates a new continuation job. User cancellation signals the active provider event in the service instance and durably fences other instances. Shutdown JobInterrupted propagates to Worker; no BaseException failure conversion. Domain failure is persisted as failed even though the safe queue handler acknowledges its handled failure with an error_code result.

Readiness preflight is intentionally absent by default: execution_not_configured. Local/demo implementation remains prohibited through IndexService authority. Coordinator supplies execution_preflight(content) later; that callback receives pinned canonical content, not model-created grants. Readiness rechecks availability, current implementation selection, retained/current snapshots, explicit retain choices, blocking answers, one write target and scope revision. Current index freshness never claims live GitHub HEAD freshness.

Exports use canonical content/hash, readable sections and source links. Per R1, exported text remains plain text with identifiers, underscores, quotes and markup preserved; recognizable credentials/private host paths are conservatively suppressed, and revoked source is unavailable. UI must display it as plain text (not parse untrusted markup). No generic text filter can guarantee detecting every arbitrary secret supplied by a user; this backend never reads provider credentials into plan/message payloads. HTTP/UI must retain plain-text rendering for exported prompts. Conversation export explicitly supplies a next_cursor for continued history. Purge conservatively tombstones entire affected conversations and plans; deletion favors removing duplicated context over preserving unrelated text in a mixed conversation.

Index candidate remains unapproved. Its README/profile catalog limitation is recorded in evaluation.md. No dependency source, migrations, HTTP, shared legacy files or board changed here. Final review/corrections and dependency integration remain coordinator gates.

## R1 additive shapes and lifecycle fixes

- `ConversationService.export(id, limit=100, cursor=None)` returns `{conversation_id, markdown, next_cursor}`. Pass the returned cursor back to this same method to export the next message page; limit 1..100. Root owns HTTP query wiring.
- `ConversationService.list_runs(id, limit=50, cursor=None)` returns `{items,next_cursor}` with stable created_at/id ordering. `get(id)` returns at most 100 runs plus `runs_next_cursor` and boolean `runs_truncated`; messages and their run scope/provenance lookup are also bounded. No silent run-history truncation.
- Assistant messages and public runs now include `profile_version_id`, `model` and `destination` (`{kind,host}` or null before a provider result). These are selected fields from actual stored generation metadata, not the currently assigned profile or model-provided declarations. Failed validated generations retain actual provenance; retry clears stale provenance until a new result. No secretrefs, endpoint paths, headers, prompts or full queue metadata are exposed.
- Source-sharing policy is conservative for nonempty repository scope and includes cited prior history even when current retrieval has zero hits. All included history citations and scope are checked again immediately before the call.
- Full user request remains bounded at 16000 UTF-8 bytes and is persisted/sent intact. Only routing/search use a separate 3000-byte UTF-8-safe retrieval query. Invalid oversized input fails before any persistence.
- Standalone Worker callers receive an Ask-owned lease renewal thread during provider generation, at lease_ms/3 (maximum 5 seconds); it fences token/owner/expiry/cancel/scope before calling public JobQueue.heartbeat under the same Store lock. It never revives an expired lease, signals provider cancellation on ownership loss and joins before returning. This does not assume ApplicationServices._maintained is present. Existing root wrapper may coexist. No shared queue helper or platform change was needed.
- get_run, list_runs/get, send and retry reconcile active domain runs backed by terminal queue jobs. Queue cancellation maps to cancelled; exhausted lease jobs map to failed/lease_expired; other unexpected terminal queue outcomes map to failed/job_terminated. Durable domain completion before queue acknowledgement remains replay-safe. Queued cancellation sets finished_at and clears stale queue errors atomically; leased cancellation retains queue ownership until acknowledgement.
- Mid-run retrieval revocation/exclusion reports scope_unavailable rather than invalid_output. Unknown/unvalidated model JSON still reports invalid_output. Slash tokens only identify explicit scope if they equal known current catalog names; path/read-write expressions cannot override valid pins or conversation scope.
